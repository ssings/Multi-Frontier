# Qdrant TLA+ Generation Interface Constraints

## 0. Document Purpose and Precedence

This document specifies the fixed module order, public names, cfg/helper interfaces, action boundaries, and non-weakenable properties for the Qdrant Frontier-based TLA+ model.

Constraint precedence:

```text
Qdrant TLA+ Generation Interface Constraints
> Qdrant Frontier-based Formal Modeling Specification
> Frontier-based Formal Modeling Method
> Milvus Reference Code
```

If any conflict occurs, the document with higher precedence must be followed. The fixed cfg and `QCfgHelpers.tla` must not be modified merely to accommodate generated code.

---

## 1.  Output Files

The LLM must generate exactly the following eight TLA+ files, and no others:

```text
QCore.tla
QAuth.tla
QWrite.tla
QReplica.tla
QMigration.tla
QSearch.tla
QFrontierInterface.tla
QIntegrated.tla
```

There is also one fixed support file supplied in advance by the experimenter:

```text
QCfgHelpers.tla
```

`QCfgHelpers.tla` is not generated by the LLM, is not counted among the eight generated files, and must not be modified during iterative repair.

Requirements:

```text
The file name must exactly match the MODULE name;
all eight generated files must exist and be non-empty;
no Markdown code fences may remain in generated TLA+ files;
each module must begin with a standard MODULE header and end with ====;
no additional intermediate modules may be generated;
the root module is fixed as QIntegrated.tla.
```

---

## 2. Mandatory Module Dependency Order

The dependency order must be exactly:

```text
QCore
  -> QAuth
  -> QWrite
  -> QReplica
  -> QMigration
  -> QSearch
  -> QFrontierInterface
  -> QIntegrated
```

The corresponding `EXTENDS` constraints are:

```text
QAuth              EXTENDS QCore
QWrite             EXTENDS QAuth
QReplica           EXTENDS QWrite
QMigration         EXTENDS QReplica
QSearch            EXTENDS QMigration
QFrontierInterface EXTENDS QSearch
QIntegrated        EXTENDS QFrontierInterface, QCfgHelpers
```

Required standard modules may also be included in `EXTENDS`, but the business-module dependency direction above must not be changed.

The following are strictly prohibited:

```text
QSearch EXTENDS QFrontierInterface;
QSearch referencing operators defined in QFrontierInterface;
QFrontierInterface EXTENDS QIntegrated;
an earlier module referencing a later module;
cyclic EXTENDS or cyclic INSTANCE dependencies;
adding QFrontierBase or any other intermediate business module.
```

This order represents the static dependency order, not the runtime execution order of actions.

## 3.  cfg Root Interface

The  cfg uses:

```text
SPECIFICATION Spec
```

`QIntegrated.tla` must expose:

```text
Init
Next
GlobalVars
Spec
```

with the  definition:

```text
Spec == Init /\ [][Next]_GlobalVars
```

The  cfg checks the following invariants, whose names must match exactly:

```text
GlobalTypeInvariant
AuthSafety
WalBeforeApply
ReplicaNotAheadOfWAL
FrontierSafety
MigrationSafety
```

These invariants must not be renamed, removed, commented out, replaced with `TRUE`, or bypassed by modifying the cfg.

## 4.  Constants and CFG-Helper Interface

### 4.1 Model Constants Declared by QCore

`QCore.tla` must declare:

```text
Principals
Nodes
Shards
Collections
Points
Replicas
writeConsistencyFactor
replicas
replicaNode
pointShard
pointCollection
shardCollection
```

`Replicas` is the set of replica objects, whereas `replicas` is the function mapping each Shard to its set of replicas. These two identifiers must not be confused.

Types:

```text
writeConsistencyFactor \in [Collections -> Nat]
replicas               \in [Shards -> SUBSET Replicas]
replicaNode            \in [Replicas -> Nodes]
pointShard             \in [Points -> Shards]
pointCollection        \in [Points -> Collections]
shardCollection        \in [Shards -> Collections]
```

The following operators must be defined:

```text
CollectionOfShard(s) == shardCollection[s]
PointsOfShard(s) == {pt \in Points : pointShard[pt] = s}
ReplicasOfPoint(pt) == replicas[pointShard[pt]]
```

The following conditions must be checked:

```text
Principals # {}
Nodes # {}
Shards # {}
Collections # {}
Points # {}
Replicas # {}
\A pt \in Points : pointCollection[pt] = shardCollection[pointShard[pt]]
\A s \in Shards : replicas[s] # {}
\A c \in Collections : writeConsistencyFactor[c] >= 1
```

### 4.2 Model Values Are Not Part of the Public Code Interface

The following names appearing in the fixed cfg:

```text
P1, P2, N1, N2, N3, S1, C1, PT1, PT2, R1, R2, R3
```

are TLC model values. `QCore.tla` must not declare each of these names as an individual constant, and business logic must not hard-code them.

### 4.3 Fixed Helper Names

Function-valued constants in the fixed cfg use:

```text
writeConsistencyFactor <- WriteConsistencyFactorCfg
replicas               <- ReplicasCfg
replicaNode            <- ReplicaNodeCfg
pointShard             <- PointShardCfg
pointCollection        <- PointCollectionCfg
shardCollection        <- ShardCollectionCfg
```

The following zero-argument operators must be provided by the fixed `QCfgHelpers.tla`:

```text
WriteConsistencyFactorCfg
ReplicasCfg
ReplicaNodeCfg
PointShardCfg
PointCollectionCfg
ShardCollectionCfg
```

Generated code must not:

```text
output or modify QCfgHelpers.tla;
redefine helpers with the same names;
change the <- helper names used in the cfg;
move complex function values back into the cfg;
weaken invariants through helper definitions.
```

## 5.  Enumerations

```text
Operations == {"Read", "Write", "Manage", "Migrate"}
ReadConsistencyLevels == {"One", "Majority", "All"}
WriteStates == {"None", "WalLogged", "Applied"}
MigrationStates == {"Stable", "Migrating", "Activated"}
```

The strings above must not be confused with model values. A `"Failed"` state without a supporting action must not be retained.

## 6.  QCore Interface

`QCore` must be responsible for:

```text
declaring all model constants;
defining the fixed enumerations;
defining CollectionOfShard, PointsOfShard, and ReplicasOfPoint;
defining CoreAssumption;
defining CoreTypeOK;
defining the majority predicate.
```

The majority predicate should preferably be written as:

```text
HasMajority(owned, all) ==
    2 * Cardinality(owned) > Cardinality(all)
```

The model must not depend on an unimported or unnecessary `Floor` operator.

## 7.  QAuth Interface

### 7.1 Variables

```text
permission
```

Type:

```text
permission \in [Principals -> [Collections -> SUBSET Operations]]
```

The following must be defined:

```text
AuthVars
InitAuth
NextAuth
CanAccess(p, c, op)
GrantPermission(admin, target, c, op)
RevokePermission(admin, target, c, op)
AuthTypeOK
```

`Manage` subsumes Read, Write, and Migrate permissions and also permits Grant/Revoke operations.

The initial permission state must include at least one authorized principal and at least one unauthorized principal so that both authorization and rejection paths are covered. Action semantics must not depend on specific names such as `P1` or `P2`.

---

## 8.  QWrite Interface

### 8.1 Variables

```text
writeState
wal
applied
ackSet
replicaHas
shardData
lastWrite
```

The following must be defined:

```text
WriteVars
InitWrite
NextWrite
ReceiveWrite(p, pt)
RejectWrite(p, pt)
ReplicaAck(pt, r)
CommitWrite(pt)
SyncReplica(pt, r)
WriteTypeOK
```

### 8.2 Mandatory Semantics

```text
ReceiveWrite: if authorized, place the Point into the WAL; it must not be committed unconditionally at the same time;
RejectWrite: record only the rejection and do not modify database state;
ReplicaAck: only a replica of the Point's Shard may acknowledge the Point;
CommitWrite: the Point may become Applied only after the acknowledgement count reaches writeConsistencyFactor;
CommitWrite: install the Point into shardData of its Shard;
SyncReplica: after a Point becomes Applied, remaining replicas may continue to obtain that Point;
lastWrite: preserve the authorization result at execution time.
```

---

## 9.  QReplica Interface

`QReplica.tla` must not introduce additional state variables. It defines only derived operators:

```text
ReplicaContains(pt)
ReplicaSelections
Visible(pt, level, sel)
ReplicaTypeOK
```

 semantics:

```text
ReplicaContains(pt) ==
    {r \in ReplicasOfPoint(pt) : pt \in replicaHas[r]}
```

Visibility:

```text
"One"      at least one valid replica contains the Point;
"Majority" more than half of the valid replicas contain the Point;
"All"      all valid replicas contain the Point.
```

`Visible` is not responsible for checking commit status or migration safety.

---

ReplicaSelections ==
    {sel \in [Shards -> Replicas] :
        \A s \in Shards :
            sel[s] \in replicas[s]}

## 10.  QMigration Interface

### 10.1 Variables

```text
shardOwner
shardLocation
migrationState
migrationSrc
migrationDst
copiedData
lastMigration
```

An `activeReplica` variable that redundantly represents the unique owner already expressed by `shardOwner` must not be added.

The following must be defined:

```text
MigrationVars
InitMigration
NextMigration
StartMigration(p, s, src, dst)
RejectMigration(p, s, src, dst)
AdvanceMigration(p, s)
ActivateMigration(p, s)
FinishMigration(p, s)
MigrationSafe(pt)
MigrationTypeOK
```

### 10.2 Mandatory Semantics

```text
StartMigration: src is the current owner, dst differs from src, and the caller is authorized;
RejectMigration: record only the rejection;
AdvanceMigration: the first version is fixed to copiedData'[s] = shardData[s];
ActivateMigration: all currently committed data of the Shard must already be contained in copiedData[s];
ActivateMigration: update shardOwner and install copiedData into shardData;
FinishMigration: copiedData may be cleared, but committed data in shardData must not be lost;
lastMigration: preserve authorized and phase at execution time.
```

## 11.  QSearch Interface

### 11.1 Dependency Boundary

```text
QSearch EXTENDS QMigration
```

`QSearch` must appear before `QFrontierInterface`; therefore, it must not contain any of the following names:

```text
WriteFrontier
CommitFrontier
ReplicaFrontier
QueryFrontier
MigrationFrontier
SearchFrontier
FrontierSafety
```

### 11.2 Variables and Operators

Variables:

```text
searchResult
lastSearch
```

The following must be defined:

```text
SearchVars
InitSearch
NextSearch
SearchEligibleSet(p, c, level, sel)
Search(p, c, level, sel)
RejectSearch(p, c, level)
SearchTypeOK
```

 definition:

```text
SearchEligibleSet(p, c, level, sel) ==
    {pt \in Points :
        /\ pointCollection[pt] = c
        /\ CanAccess(p, c, "Read")
        /\ pt \in applied
        /\ Visible(pt, level, sel)
        /\ MigrationSafe(pt)}
```

A successful Search must satisfy:

```text
searchResult' = SearchEligibleSet(p, c, level, sel)
```

An arbitrary subset must not be used; otherwise, the model could permanently omit eligible results or return the empty set.

`lastSearch` must contain at least:

```text
kind
principal
collection
level
result
authorized
executed
```

## 12.  QFrontierInterface

### 12.1 Module Boundary

```text
QFrontierInterface EXTENDS QSearch
```

This module must:

```text
appear second to last;
declare no VARIABLE;
define no InitX, NextX, or state action;
not modify the semantics of preceding modules;
define only Frontiers, related safety predicates, and FrontierSafety.
```

### 12.2  Frontier Names

```text
WriteFrontier
CommitFrontier
ReplicaFrontier(r)
QueryFrontier(level, sel)
MigrationFrontier
SearchFrontier(p, c, level, sel)
```

 semantics:

```text
WriteFrontier == wal
CommitFrontier == applied
ReplicaFrontier(r) == replicaHas[r]

QueryFrontier(level, sel) ==
    {pt \in CommitFrontier : Visible(pt, level, sel)}

MigrationFrontier ==
    {pt \in CommitFrontier : MigrationSafe(pt)}

SearchFrontier(p, c, level, sel) ==
    SearchEligibleSet(p, c, level, sel)
```

### 12.3  Safety Predicates

The following must be defined:

```text
CommitFrontierSafety
ReplicaFrontierSafety
QueryFrontierSafety
MigrationFrontierSafety
SearchFrontierSafety
SearchResultSafety
FrontierSafety
```

The most recent successful Search must satisfy:

```text
lastSearch.result =
    SearchFrontier(lastSearch.principal,
                   lastSearch.collection,
                   lastSearch.level)
```

`FrontierSafety` must combine the internal properties above and must not be defined directly as `TRUE`.

## 13.  QIntegrated Interface

### 13.1 Dependencies

```text
QIntegrated EXTENDS QFrontierInterface, QCfgHelpers
```

`QIntegrated` must be the final business module.

### 13.2 Initialization

```text
Init ==
    /\ CoreAssumption
    /\ InitAuth
    /\ InitWrite
    /\ InitMigration
    /\ InitSearch
```

All variables must be initialized through this path.

### 13.3 Global Variables

The following must be defined:

```text
GlobalVars
```

and must cover:

```text
AuthVars
WriteVars
MigrationVars
SearchVars
```

No variable may be omitted, duplicated, or referenced without being declared.

### 13.4 Integrated Wrapper Actions

Wrapper actions covering all four action classes must be defined:

```text
IntegratedAuthAction
IntegratedWriteAction
IntegratedMigrationAction
IntegratedSearchAction
```

Each wrapper must:

```text
invoke an action from a preceding module;
explicitly use UNCHANGED for all other global variables not modified by that action.
```

 definition:

```text
Next ==
    \/ IntegratedAuthAction
    \/ IntegratedWriteAction
    \/ IntegratedMigrationAction
    \/ IntegratedSearchAction
```

Local actions must not be inserted directly into the global `Next` if doing so leaves variables from later modules unspecified.

## 14.  Invariant Semantics

### 14.1 GlobalTypeInvariant

It must combine at least:

```text
CoreTypeOK
AuthTypeOK
WriteTypeOK
ReplicaTypeOK
MigrationTypeOK
SearchTypeOK
```

`QFrontierInterface` has no state variables and therefore does not require a separate `FrontierTypeOK`, unless such an operator checks the result types of Frontier operators and its name does not conflict with operators in other modules.

### 14.2 AuthSafety

```text
the most recent successful write, search, and migration must have authorized = TRUE at execution time;
unauthorized attempts must take only the corresponding Reject branch;
historically successful operations must not be revalidated against the current permission state.
```

### 14.3 WalBeforeApply

```text
applied \subseteq wal
```

### 14.4 ReplicaNotAheadOfWAL

```text
\A r \in Replicas : replicaHas[r] \subseteq wal
```

### 14.5 FrontierSafety

It must combine at least:

```text
CommitFrontier \subseteq WriteFrontier
\A r \in Replicas : ReplicaFrontier(r) \subseteq WriteFrontier
\A level \in ReadConsistencyLevels : QueryFrontier(level, sel) \subseteq CommitFrontier
MigrationFrontier \subseteq CommitFrontier
SearchFrontier(p, c, level, sel) = SearchEligibleSet(p, c, level, sel)
a successful lastSearch.result equals its corresponding SearchFrontier
```

### 14.6 MigrationSafety

It must guarantee at least:

```text
shardOwner[s] \in shardLocation[s]
the migration source is the current owner
the migration target differs from the source
before activation, the target has copied all currently committed data
Applied Points are not lost after owner migration and FinishMigration
```

## 15. Prohibited Degenerate Implementations

The following are prohibited:

```text
adding QFrontierBase or another intermediate business module;
swapping the order of QSearch and QFrontierInterface;
allowing QSearch to use SearchFrontier;
allowing QFrontierInterface to declare variables or actions;
defining an invariant as TRUE;
defining Next as FALSE, TRUE, or only UNCHANGED;
permanently fixing successful Search results to the empty set;
requiring only that the result be an arbitrary subset of the candidate set;
deleting Grant, Revoke, write, synchronization, query, or migration actions;
deleting or weakening invariants referenced by the fixed cfg;
modifying the fixed cfg or QCfgHelpers.tla;
regenerating the entire model to repair a local error.
```

---

## 16. Incremental Repair Output Constraints

The initial generation must output all eight modules.

During iterative repair:

```text
use the current on-disk version as the baseline;
modify only the necessary files directly involved in the current error;
preserve all unrelated files unchanged;
do not change the fixed module order or public names;
do not modify the cfg or QCfgHelpers.tla;
prefer returning a unified diff;
if a reliable diff cannot be produced, return only the complete contents of files that were actually modified;
after modification, rerun the static checks, SANY on all modules, and the Integrated TLC smoke test.
```
